# 壁打ちの暫定プランを司令塔へ渡す — 案（2026-10-06、未実装）

## いま

- 「05 PLAN に送る」は `Sparring.planMessage(steps)` を**司令塔への次のメッセージ**として stdin に流す（`SparPanels.toPlan`）。
- 司令塔は返事の `PLAN:` / `NOW:` / `DONE:` 行で計画を積み、AT22 がそれを読んで 05 PLAN に出す（`adoptPlan`）。
- 弱いところ: 司令塔が作業中だと届くのは次のターン。返事の行の書式に頼る（崩れると積まれない）。会話が増えると文脈を食う。

## 案 A: スキル＋ファイル（いちばん小さい）

1. AT22 が合意した手順を記憶DB の `sessions/each/<司令塔ID>.plan.md`（または worktree ごとの `PLAN.md`）に書く。
   書式は frontmatter ＋ 番号つきの行（`- [ ] 1. …` / `- [x]`）。
2. 同梱スキル `at22-plan` に「このファイルを読んで、手順を始めたら `- [~]`、終えたら `- [x]` に書き換える」と書く。
3. AT22 はファイルを見張り（記憶DB の読みと同じ裏の周回）、05 PLAN を更新する。司令塔には「計画を置いた」と1行だけ送る。

- 良いところ: サーバーが要らない。claude と grok（`~/.grok/skills`）はスキルを読む。書式がファイルに固定され、返事の行を読まなくて済む。
- 気をつけること: 書き換えは Edit の承認に乗る（worktree の外の記憶DB なので Gate.risk では高）。`Edit(//…/plan.md)` を許可の並びに足すか、低に数える例外を足す。

## 案 B: AT22 が MCP サーバーを立てる（いちばんきれい）

1. AT22 が手元に MCP サーバー（`127.0.0.1` の Streamable HTTP、起動ごとの鍵つき）を立てる。
   道具: `at22_plan_get`（合意した手順と決定事項）、`at22_plan_progress(step, state)`、`at22_decisions_get`。
2. claude は起こす時に `--mcp-config` で繋ぐ（`Launcher.common` に足すだけ）。ACP の相手は `session/new` の `mcpServers` で渡せる（今は `[]`）。
3. 05 PLAN は MCP の呼び出しで直接更新する。`PLAN:` 行の約束（`Sparring.planProtocol`）は要らなくなる。

- 良いところ: 構造化されていて、書式の崩れが無い。司令塔が作業中でも、次に道具を呼んだ時に最新を取れる。codex（app-server も MCP を持つ）にも同じ口で渡せる。
- 気をつけること: アプリの中に HTTP サーバー（Network.framework）を持つ。`mcp__at22__*` は Gate.risk で高なので、AT22 自身の道具は低に数える例外を足す。

## 案 C: 今のまま、届け方だけ直す

- 作業中なら Hydra の報告と同じ送り待ち（`hydraOutbox`）に入れて、ターンの終わりに送る。行の書式は今のまま。

## 勧め

まず **案 A**（スキル＋ファイル）。いまの部品（記憶DB の見張り・同梱スキル・設定 06 で入れる）だけで組める。
司令塔とのやり取りを増やす予定（決定事項の参照・進み具合の報告・Hydra の指示書）があるなら、その時に **案 B** へ移す。
