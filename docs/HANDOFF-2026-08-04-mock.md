## 1. 最初に見てほしいこと

**目で見る手段を足した。** 窓を開かずに PNG を1枚焼く:

```
swift run AT22 --shot /tmp/a.png 1440 900 --transcript <path.jsonl> --gate
swift run AT22 --shot /tmp/b.png --board --transcript <path.jsonl>
```

前回の §1 が「見え方を継続的に確かめる手段はまだ無い／同じ失敗が繰り返されている」と
書いていた穴。`Snapshot.swift` と `AT22App` の `--shot` がそれ。

**制約:** `TimelineView` と `ScrollView` の中身は `ImageRenderer` が組まないので、
盤面は `--board` でしか写らない（外枠は `--shot`）。`Menu` / `Toggle` / `TextField` も
焼けず黄色い箱になる。**動き（ビームの脈・虹・破線の流れ）は1コマしか写らない。**

実機で見てほしいのは、焼いても分からないこの4つ:

1. レールの `G` の赤い点が、門が止まっている間だけ明滅するか
2. エージェント行の横枝が、稼働中の1本だけ赤く流れるか
3. 虹（特大の書き込み）が今まで通り循環しているか
4. ⇧⌘T のモーダル、セルのクリック、Esc の畳み順（吹き出し → タスク → エゴビュー）

## 2. 入れたもの

### 2-1. 外枠（新規 `Chrome.swift`）

`CockpitView` の根を `VStack { タイトルバー / (レール・サイドバー・盤面) / ステータスバー }` に組み替えた。

| 部品 | 中身 |
|---|---|
| タイトルバー 48pt | `AT22`（2 が赤）／中央に刻印 `GLASS COCKPIT · <セッション名> · <ID>`／LV ノブ／`消費 53.4M` |
| 左レール 56pt | `K 会話`(⇧⌘M) `T 作業` `G 門`(停止中は `停止N`＋赤い点) `S 設定`(⌘,) |
| タブ行 | `a 作業 / b 構造 / c 壁打ち` ＋ 右端に文脈計器（72×6・85% に危険の目盛り） |
| 進行表の帯 | `Cockpit.progressStrip` が畳んだ並び ＋ ⇧⌘T のキーキャップ |
| ステータスバー 28pt | `Lv.3 気にかけてる` `門 01 停止中` … `<ID>` |

- **信号機は自前で描いていない。** `.windowStyle(.hiddenTitleBar)` にして左端 78pt を空け、
  OS が同じ位置に描くのに任せてある。モックの3つの丸は HTML 都合の作り物
- `a` / `b` / `c` の1文字でタブを飛ぶ（`CockpitKeys`）。壁打ちに未保存があると止まる
- `minWidth` を 720 → **776**（レール 56pt ぶん）
- ツールバーに残したのは「非アクティブを消す」「クリア」だけ

### 2-2. 金属の質感（新規 `Texture.swift`）

DS の画像素材（`hairline-tile.png` / `spun-disc.png` / `noise-field-white.svg`）は
**取り込めなかった**——MCP の `get_file` は 256KiB 上限で、取れてもバイト列が base64 で
モデルの文脈を丸ごと通る（3枚で数十万トークン）。同じ作り方を Swift で直接書いてある:

- ヘアライン … 1px の縦筋を途切れさせながら敷き詰めたタイル（256px）
- スピン … 同心の工具目 **＋** 中心から放射する幅広のスペキュラ楔（両方要る。
  同心だけだと年輪に、放射だけだと艶が死ぬ）
- 網点 … 大きい雲をしきい値に通して粒に落としたもの

種を固定した乱数で焼くので毎回同じ模様になる（`StillLayer` の描き直し判定が効いていても
肌だけがちらつくのを避ける）。**素材の画像が手に入ったら `Image(nsImage:)` に差し替えれば
呼び出し側は変わらない。**

### 2-3. エージェント帯を行に（いちばん大きい書き換え）

`CockpitLayout.compute` の「深さ＝横軸の列」を捨てて、**司令塔の箱＋縦1本の点線レール＋行**に。

```
03 エージェント 6
[C0 司令塔  opus-5 460 100%]
  编集166 読取136 検索67
       ┊
       ├╌╌╌ W1 │ 名前 │ Target.swift を編集中 │ haiku-4.5 41 17% │ [実行中]
       ├╌╌╌ W2 │ …                                              │ [終了]
       │ ▯ 紙 28×40
       └╌╌╌ G  │ 検査ワーカー │ 門で停止中 — 右の欄で応答        │ [待機]
```

- 新しい寸法は `CockpitLayout` の「エージェントの帯」節にまとめてある
- **紙は 62×88 → 28×40 に縮めた。** 中身は行の meta と門のパネルが持つので、
  紙は「そこで止まっている」ことだけを指す。列の間に通り道を作る必要が消えたのが、
  列をやめられた理由
- 門は**紙と行の両方**で出る。どちらを押しても開く（`gateRects` に両方を登録）
- 消えたもの: `orderPaper` / `orderLane` / `orderPoints` / `orderLaneX` /
  `orderPaperRect` / `orderLines` / `beamPoints` / `beamCorridor` / `pointOnPolyline`

### 2-4. ビームを外した ⚠

モックの作業画面はエージェント帯とファイル帯を1本の罫で断ち切っていて、
**線の通る道が無い**。関係は文字で語る形に変えた:

- 行の側 … `CockpitLayout.rowMeta` が「いま触っているファイル」を必ず出す
- セルの側 … `CellBox.tag` が「W5 書込中」を返す

**この2つが唯一の手掛かりになった。** どちらかを削ると、どのエージェントが何を触っているか
画面から辿れなくなる。p0 の `agentRowsHangFromTheRail` がそこを見ている。

### 2-5. 門を明るい金属パネルへ（`GatePanel`）

サイドバーの停止カードを畳んで、**エージェント帯の右 288pt** に戻した。
レールの上に立つ紙と同じ高さに並ぶので、どの行が止まったのかが目で繋がる。

- スピン仕上げの明るい板＋四隅のネジ。**画面で唯一の明るい面**（2枚に増やすと指す力が半減する）
- 許可（⇧⌘G）／書換／却下がここで完結。書換はその場でテキスト欄が開く
- `GateAnswer`（420pt のペイン）と `ConversationSidebar.gateCard` は削除
- `gateFailed`（答えを書けなかった時の欄）はパネルへ移した——黙って消すと司令塔が待ち続ける
- ✕ で畳んでも答えたことにはならない。レールの `G` から開き直せる

### 2-6. 凡例を章見出しの右へ

## 3. やっていない — 判断が要る

### 3-1. 壁打ちの「材料」列

モックは `材料 220pt │ 記憶DB 250pt │ 編集欄` の3列で、材料に 48件（企画ノート／過去の計画／
README）が並ぶ。**何がこの列に入るのか決められなかった**ので入れていない。

前回の引き継ぎ §2 は「壁打ちモードは記憶DBだけを1列で出す。材料は落とした」と書いていて、
モックはそれを戻している。`Memory.swift` にデータ源を足すことになるので、
**「材料」が何を指すのか**（Obsidian の構想ノート？ プロジェクト直下の docs？ 記憶DBの
プロジェクト階層？）を決めてほしい。決まれば列そのものは小さい。

いまの壁打ちは `記憶DB │ 編集欄` の2列のまま。章見出し（`06 記憶DB N`）は入っている。

### 3-2. 構造モードの4列フラット格子

モックは全ファイルを4列の格子に平らに並べる。実装はディレクトリごとのカードのまま
（ホバーで関係が浮かび無関係が沈む挙動と、章見出し・凡例は入っている）。

カードの方がどのディレクトリの何かが分かるので、**平らにする方が情報が減る**。
モックに完全に合わせるかどうかは好みの問題なので、そのままにしてある。

### 3-3. 虹は残したまま

決定通り `WriteTier.rainbow` も `p0-selfcheck.swift:957` も触っていない。
モックの凡例（`二重線=上位2%`）と両立している——二重下線の上に虹が乗る積み方は前のまま。

## 4. 触った時に連動するところ

前回のぶんに加えて:

- `markColumn` → `nameLimit` / `subLimit` / `naturalCellWidth`（変わらず）
- **`railOffset` / `rowOffset` → 紙の置き場**（`gatePaperInset` が両者の間に収まる前提。
  p0 の `gateShowsAsPaperAndRow` が「紙が行の欄に食い込まないこと」を見ている）
- **`agentHeader` → 章見出しの高さと、構造／壁打ちのカード開始位置**。
  ここを変えると `structureStaysInsideTheSelectedProject` の期待値も動く
- `Cockpit.keptCompleted` → 進行表の帯の畳み方（`progressStrip`）と一覧の対比検査
- `ModeRail.width` → `AT22App` の `minWidth`
- `StillLayer.==` は `steady / mode / hovered / contentHeight` のまま。
  **外枠は SwiftUI 側なので、この比較の外で普通に更新される**
