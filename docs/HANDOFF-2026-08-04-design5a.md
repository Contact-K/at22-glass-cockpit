# 引き継ぎ 2026-08-04 — デザイン案 5a への寄せ（第1段）

デザイン資料「Mac向けオーケストレーターUIデザイン」の **5a（ペダル筐体・DS準拠）** を土台に、
実装側を寄せた。**このセッションは Linux なので `swift build` も `p0-selfcheck` も回していない。
最初にやることはビルドと p0 検査。**

---

## 1. 最初に確認してほしいこと

```bash
swift build
swift p0-selfcheck.swift          # あるいは README:289-297 のコマンド
```

`p0-selfcheck` は SwiftUI を一切リンクせずに
`Transcript / Cockpit / CockpitLayout / Structure / Category / Memory / Gate / Launcher / Snowman`
をコンパイルする。**今回 `Category.swift` と `CockpitLayout.swift` に手を入れたので、
ここが通るかどうかが最初の関門。** どちらにも `import SwiftUI` は足していない（確認済み）。

ビルドが通ったら、目で見て確かめてほしいのは4つ:

1. ファイルセルの左端に刻印（実・検・ノ・設・資・中黒）が出て、名前の左端が全セルで揃っているか
2. 画面の赤が「いま動いているもの」だけに付いているか（他は無彩色か）
3. 門が止まった時、サイドバーの入力欄の真上にカードが出て、⌘⇧G で許可できるか
4. 区切り線・凡例のスウォッチ・雪だるまゲージのトラックが、暗い地の上で視認できるか（半透明トークンの二重掛けで消えていないか）

### 暗い地の上での見え方（数値の目安）

「消えた／明るすぎる」は半透明の掛け算でいちばん起きやすい。地は `#0E0E0E`（カーボン黒）。
主要な線と面の実効色を出しておくので、目で見て明らかにずれていたら報告してほしい。

| どこ | 指定 | 実効色 | 期待 |
|---|---|---|---|
| チップの非稼働枠 | `rule.opacity(0.45 × fade)` fade=1.0 | `#444441` | 細いが輪郭として追える |
| チップの非稼働枠（終了済 fade=0.55） | `rule.opacity(0.2475)` | `#2A2A28` | 存在は分かるが沈んでいる |
| 親子の破線（非稼働） | `rule.opacity(0.45)` | `#444441` | 主張しない案内線 |
| 凡例上端の罫線 | `rule.opacity(0.45)` | `#444441` | 章の切れ目として読める |
| セル「触った」の地 | `Palette.ink.opacity(0.06)` | `#1E1E1D` | 地よりわずかに明るい面 |
| セル「未接触」の地 | `Palette.ink.opacity(0.02)` | `#131312` | ほぼ地と同じ（文字の暗さで区別する） |

`Palette.hairline` / `Palette.border` は**それ自体が半透明**なので、呼び出し側で `.opacity()` を掛けると乗算で二重に薄まる。掛ける前提の色が要るときは不透明の `Palette.inkTertiary` を使う（`CockpitCanvas.rule` がそれ）。
見え方を継続的に確かめる手段（SwiftUI Preview か、状態を並べたスクリーンショット）は**まだ無い**。同じ失敗が繰り返されている領域なので、次の一手の候補。

## 2. 入れたもの

### 2-1. `Palette.swift`（新規・SwiftUI 側）

5a のトークン層。色・余白・角丸・線幅・文字サイズ・字送りをここ1箇所に集めた。

規律は3つだけ:

- **色は意味のときだけ。** 地・線・文字はすべて無彩色。色が付くのは
  「いま」（accent＝赤）と success / warning / danger の3つ
- **余白は固定スケール**（4 / 8 / 16 / 24 / 32 / 48 / 64）。半段（2 / 6 / 12）は部品の内側だけ
- **奥行きは線と明度差で出す。** 柔らかい影で浮かせない

**`CockpitLayout` からは参照しないこと。** あちらは SwiftUI 抜きで p0 から叩ける側に残してある。
色は SwiftUI 側、寸法は非 SwiftUI 側、という既存の分割はそのまま。

### 2-2. カテゴリの色分けを廃止 → 刻印記号

- `FileCategory.mark`（`Category.swift`）を追加。`title` の1文字目を採る規則。
  `.other` だけ中黒「・」（1文字目だと凡例が「他 他」になる）
- `CockpitCanvas.categoryInk` を**削除**。セル左端の3pt の色帯 → 刻印1文字に置き換え
- 凡例2行目は色見本の並びから「記号：実 実装 ／ 検 検査 ／ …」の対応表に変更。
  出ているカテゴリだけを `allCases` 順で出す挙動はそのまま
- `CockpitLayout.markColumn = 14` を新設。`nameLimit` / `subLimit` / `naturalCellWidth`
  の3箇所に連動させてある（**ここを変えるならこの3つも一緒に**）

なぜ: 6色を配ると状態の色（書き込み中・フラグ・稼働中）と同じ画面で競り合い、
「色が付いている＝何か起きている」が読めなくなる。記号は無彩色で置けるので色の予算が空く。

### 2-3. 色の意味づけを組み直した

| 何 | 前 | 後 |
|---|---|---|
| 書き込み中 (`live`) | 緑 #1D9E75 | accent 赤。**画面で「いま」を指す唯一の色** |
| 読み取り中 | 深緑のリング | 無彩色のリング（起きているだけで、変わってはいない） |
| フラグ (`flag`) | 橙 | warning 琥珀（DS の値） |
| チップ稼働枠 (`agentOn`) | 紫 | accent 赤 |
| セルのホバー | 紫のかぶせ | 白のごく薄いかぶせ（明度差） |
| エラー | `calledBy` を流用 | **`CockpitCanvas.error` に切り出した** |
| 地 (`background`) | システム動的色 | カーボン黒 固定 |

エラー色を切り出したのは、「呼ばれている元」と「エラー」が同じ色だと、
構造画面でエラーが出た時にどちらの意味で赤いのか読めないため。

**エゴビューの3方向（呼ばれている / 呼んでいる / 関連ノート）だけは色を残した。**
同じ四角の印を3つ並べる作りなので、色を取ると区別が付かない。DS の値に載せ替えただけ。

### 2-4. 会話サイドバーを罫線の行に

- 吹き出し（左右振り分け・角丸）→ **罫線で区切った全幅の行**。
  300pt 幅の欄で左右に振ると、どちらの側も本文が半分の幅しか使えない
- 話者は行頭の刻印ラベル（あなた／司令塔／思考）で語る。
  人の発言だけ地を 4% 持ち上げて、話者の入れ替わりを明度差で追えるようにした
- 章見出し「01 会話 … 件数」を追加（5a は区画に通し番号を振る）

### 2-5. 門の停止カードをサイドバーに

**答える口を1つに寄せた。** 入力欄の真上に固定で出る。

- 許可（⌘⇧G）と却下はカードで完結
- 書換だけは文章を編む場所が要るので、キャンバス側の既存の欄（`GateAnswer`）を開く
  （`ConversationSidebar.onRevise` → `CockpitView.answering`）
- 複数溜まっていても出すのは待たせている順に1件だけ。並べると「どれに答えているか」が曖昧になる
- 答えを**書けなかった時は必ず欄に出す**（`gateFailed`）。黙って消すと司令塔が待ち続ける

⌘Return は入力欄の「送る」が既に持っているので、門側は ⌘⇧G に逃がした。
同じ鍵にすると、門に答えたつもりで割り込みが飛ぶ。

### 2-6. 意図的に**触っていない**ところ

- `mode == .work` を外して、門の答えかけは表示モードを切り替えても畳まないようにした
  （門が止まっている間はどのモードでも司令塔は待っている）
- `.onChange(of: mode)` から `answering = nil` を外した。上と同じ理由

## 3. 未解決 — 判断が要る

### 3-1. 虹（特大の書き込み）が 5a と衝突している

5a は「虹色・シマーの装飾アニメを撤去」と言っている。色を意味なく5色使うのは
「色は意味のときだけ」に反する。

**が、`p0-selfcheck.swift:957` が `tier(500, huge: true).rainbow == true` を固定している。**
これは仕様として押さえられている挙動なので、勝手に外さなかった。

選べる道:

- **A. 虹を残す** — p0 に手を触れない。5a の規律とは1点だけ食い違う
- **B. 虹をやめる** — `WriteTier.rainbow` を落とし、`p0-selfcheck.swift:33, 939-957` の
  検査も一緒に直す。特大は「二重下線」だけで語らせる
- **C. 虹を accent の明滅に置き換える** — 5色を1色にする。動きは残るが色は増えない

どれにするか決めてほしい。決まれば実装は小さい。

なお**波（書き込み中に名前の上を走る不透明度のアニメ）は残した。**
色を使わず明度だけで動くので、5a の規律には触れていない。

### 3-2. 「量は下線」に寄せるかどうか

5a はファイル名の下線の太さ（1px / 2px / 3px 二重）で書き込み量を語っている。
実装は「点 → 下線 → 虹」の順に積む作りで、`CockpitLayout.swift:411-412` に
**「下線を単独で量に使うと名前が長いほど大きく見えるので一度却下した」**と残っている。

一度却下した判断なので今回は戻していない。5a に完全に合わせるなら、その理由をどう畳むかから。

## 4. まだやっていない（5a の残り）

| 5a の要素 | 現状 |
|---|---|
| 左レール（K / T / G / S のキー） | 無い。モード切替はツールバーの Picker |
| タブ（a 作業 / b 構造 / c 壁打ち） | ツールバーの segmented Picker のまま |
| 最上段の進行表（タスクの帯） | 無い。タスクは ⇧⌘T のパネルだけ。README:33-41 の記述は現行コードと合っていない |
| 最下段のステータスバー | 無い。キャンバス末尾の凡例が近い役 |
| タイトルバー（LV ノブ・文脈/消費の計器） | 無い。雪だるまバッジがサイドバーの中にある |
| エージェント欄を「行」に | チップの箱のまま。枠・数字の色だけ 5a に寄せた |

**エージェント欄をチップ → 行にするのがいちばん大きい残り。**
`CockpitLayout.compute`（深さ＝横軸の列）を組み直すことになり、
`orderLane`（紙が通る道）・`beamCorridor`（ビームの通り道）が連動する。
`CockpitLayout.swift:539-543` に「段を縦に積むと紙（88pt）が物理的に入らないので列にした」経緯がある。
5a は縦1本の点線レールに紙を重ねる作りなので成立はするが、寸法を全部引き直す必要がある。

## 5. 触った時に連動するところ（次の人向け）

- `markColumn` → `nameLimit` / `subLimit` / `naturalCellWidth`
- `cellHeight` / `tickSize` → `maxReadTicks` と設定画面の Stepper 上限（`AT22App.swift:40-52`）
- `cellGapY` → 動く層が静止版を拭う inset（`drawCard` の `-5`）
- `cardTopGap` → `beamCorridor` の帯（縮めるとビームがカードに隠れる）
- `CockpitLayout.font` を等幅以外にすると `textWidth` の係数 0.6 が崩れ、省略計算が全部壊れる
- `StillLayer.==` は `steady / mode / hovered / contentHeight` だけを比較する。
  **実行時にテーマを切り替える機能を足すなら、ここに比較を足さないと再描画されない**
  （今回は `Palette` をコンパイル時定数にしてあるので問題は起きない）
